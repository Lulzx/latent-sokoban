How evaluation works

  1. POST /api/scorecards opens a scorecard — one submission attempt. Authenticated by your API key; the key is your leaderboard identity.
  2. …/games/standard/start begins a session over 50 hidden 8×8 levels. Every frame carries the board and the goal as raw 64×64×3 bytes. The layouts never leave the server.
  3. POST /api/sessions/{id}/act sends one action: up, down, left, right. Invalid moves are no-ops that still consume a step. 80 steps per level.
  4. …/close locks the scorecard and posts it to the leaderboard. Unplayed episodes count as unsolved — no cherry-picking. Completed sessions get a public replay. Full wire schema in docs/API.md.

The rules that matter

8×8 boards, 3 crates 64×64 RGB observations ≤ 20M parameters ≤ 256 dynamics calls / action No symbolic solvers No decode-then-search

The intent: the winning system plans in a learned representation. Full rules, shared baseline (12% warmup — beatable), datasets and local tooling live in the GitHub repo. API reference at /api/docs.
